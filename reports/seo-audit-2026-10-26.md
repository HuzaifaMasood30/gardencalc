# GardenCalc SEO audit — 2026-10-26

Live site audited: https://huzaifamasood30.github.io/gardencalc/
Method: every sitemap URL and image fetched individually, source + build system
reviewed, full local rebuild (`tests.py` 41/41, `verify.py` 0 issues,
`live_audit.py` 15/15 on the rebuilt site), search-result checks for the brand
and head terms.

## Verdict in one paragraph

This is a technically strong site with an indexing *discovery and authority*
problem, not a quality or sitemap-format problem. The pages are fast, valid,
self-canonical, well interlinked and carry good schema. What is holding back
impressions is: (1) the sitemap was submitted in a way Google cannot fetch —
see `docs/search-console-sitemap-fix.md`; (2) the site is 19 days old
(first commit 2026-10-07) on a shared `github.io` subdomain with essentially
no backlinks, so Google has little reason to crawl/index 157 pages quickly;
(3) there is no analytics, so growth cannot be measured; (4) a long tail of
very similar sized-variant pages competes against strong calculator domains,
so early wins will come from the most specific queries, not head terms.

## 1. Sitemap & indexing — root cause found

Full evidence and the exact fix are in `docs/search-console-sitemap-fix.md`.
Summary:

- `https://huzaifamasood30.github.io/gardencalc/sitemap.xml` returns **200**,
  valid XML, **157 unique URLs, every one returning 200**, every referenced
  image returning 200, no noindex or redirected URLs inside.
- `https://huzaifamasood30.github.io/sitemap.xml` (host root) returns **404**.
  A sitemap submitted under a bare-host/Domain property, or pasted as a full
  URL into the URL-prefix property's box, resolves to a 404 and Google shows
  **"Couldn't fetch"**. That is a Search Console submission error, not a
  site error — re-submit `sitemap.xml` (that text only) under the URL-prefix
  property `https://huzaifamasood30.github.io/gardencalc/`.
- `robots.txt` is **not** the cause. Google only reads robots.txt from the
  host root, which a project site cannot serve; the root file 404s, which
  Google treats as "allow all". Nothing is blocked.
- Bing/other engines have at least partially indexed the homepage (it appears
  in results for `"GardenCalc" mulch calculator`, crawled ~2026-10-21), which
  confirms the pages are crawlable and indexable in principle.

## 2. What was already good (verified, not assumed)

- Titles ≤60 chars and meta descriptions 110–158 chars on all 114 articles;
  no duplicate titles or meta descriptions; exactly one H1 per page.
- Self-referencing canonicals everywhere; 404 page returns a real 404;
  merged pages use canonical + meta-refresh stubs (no noindex).
- Schema: Article + BreadcrumbList + FAQPage on articles, WebApplication on
  calculators, CollectionPage on categories, WebSite + Organization + FAQPage
  on the homepage. No fake HowTo.
- Internal linking: no orphan pages, stable same-cluster ring, contextual
  in-body links, HTML sitemap, RSS (66 items) as a fallback discovery path.
- Performance basics: self-hosted subset fonts, gzip via GitHub Pages
  (homepage 105 KB HTML → ~14 KB on the wire; CSS 39 KB → ~9 KB), lazy
  thumbnails, width/height on images (no CLS from images), JS deferred.
- Calculator parity between the Python engine and browser JS is tested.

## 3. Problems found and fixed in this audit (code changes)

1. **Four published fertilizer pages had no FAQ at all** — no visible FAQ
   section and no FAQPage rich-result eligibility (the repo's own notes price
   a missing FAQ at ~11 SEO points per page):
   `how-much-10-10-10-fertilizer-per-1000-sq-ft`,
   `how-many-pounds-of-starter-fertilizer-per-1000-sq-ft`,
   `how-many-pounds-of-lawn-fertilizer-per-1000-sq-ft`,
   `how-much-starter-fertilizer-per-1000-square-feet`.
   → Added 3 FAQs to each, with answers restated from each page's own body
   and calculator output (per the house rule that FAQ answers must be visible
   on the page).
2. **Three of those pages had ALL-CAPS, CTR-hostile titles**
   ("How Much 10 10 10 Fertilizer Per 1000 SQ FT").
   → Retitled all four in normal title case with the keyword form people
   actually type ("How Much 10-10-10 Fertilizer per 1,000 Sq Ft?"), and
   updated every stored copy of the old titles in internal links.
   `article_fix.py` still reports 0 changes (idempotent) after the edit.
3. **Duplicate image alt text site-wide.** Every figure in a cluster shared
   one identical alt string (e.g. all 21 mulch pages + their thumbnails).
   → `build.py` now prefixes the article title to the feature-figure and
   card-thumbnail alt text, so all 228+ images have unique, descriptive,
   query-relevant alt text. Visible captions are unchanged.
4. **Category pages had no BreadcrumbList schema** (articles and info pages
   already had one). → Added Home → Category breadcrumbs to all 13 hubs.
5. **Article schema `author.sameAs` pointed back at the site's own /about/
   page** — a circular signal that tells Google nothing.
   → Removed until there are real off-site profiles to list.
6. **No web app manifest.** → `build.py` now emits `manifest.webmanifest`
   (brand icons, theme colour, start URL) and `base.html` links it on
   every page.
7. **No `llms.txt`.** AI search (ChatGPT/Copilot/Perplexity-style crawlers)
   is a real discovery channel for calculator answers.
   → `build.py` now emits a `llms.txt` map of all 13 pillar calculators,
   13 categories and 101 guides with their meta descriptions.

All changes pass: `tests.py` **41/41**, `verify.py` **0 issues**,
`live_audit.py` **15/15** (157/157 pages 200, no broken links, no duplicate
titles/meta, no orphans).

## 5. Keyword & competitor research

Head terms ("mulch calculator", "concrete calculator") are held by
Omni Calculator, Inch Calculator, Lowe's/Home Depot and a crowd of new
single-purpose calculator sites (Calculatio, RoostCalc, TrueValueCalc and
several other "GardenCalc"-named sites on .io/.uk/.net). A 19-day-old
`github.io` subdomain will not outrank them soon, and the strategy already
in the data — **specific sized/intent long-tails** ("how many bags of
concrete for a 6x6 slab", "how much grass seed for 1 acre") — is the right
one. Notes:

- There are **257 unused autosuggest keywords** already mined in
  `data/keywords.json`. The best unbuilt ones (real query phrasing, existing
  calculator engine, no near-duplicate live page): gravel for a **shed
  base**, **patio base** and **paver base**; **rubber mulch for a
  playground**; paint for **trim/skirting** and **one wall**; "how much
  compost to add to garden soil". Build these before inventing new topics.
- **Cannibalisation watch:** the two starter-fertilizer pages
  (`how-many-pounds-of-starter-fertilizer-per-1000-sq-ft` and
  `how-much-starter-fertilizer-per-1000-square-feet`) target the same intent
  with the same answer. If Search Console shows both appearing for the same
  queries with neither ranking, merge the weaker into the stronger using
  `scripts/merges.py` (the stub system already handles the redirect).
  The same check applies to the mulch-for-a-tree pair.
- **Brand collision:** at least four other live sites are called
  GardenCalc (gardencalc.io, gardencalc.net, gardencalc.uk, js99.eu.org).
  Expect brand searches to be split until this site has its own domain and
  profiles; consistent naming ("GardenCalc — Free Home & Garden
  Calculators") in every off-site mention helps.
- Seasonal timing is in this niche's favour: spring (mulch, seed, soil)
  and autumn (overseeding, fertiliser) spikes. The four seasonal guides
  already exist — promote them in Feb–Mar and Aug–Sep.

## 7. What to expect, honestly

Fixing the sitemap submission removes the fetch error immediately, but
impressions grow over weeks, not days: Google typically indexes the
homepage + pillars first, then long-tails as crawl trust builds. With the
GSC fix + Request Indexing for the top 16 URLs + Bing import, a realistic
first milestone is most pillar/category pages indexed within 2–4 weeks and
first long-tail impressions (positions 20–60) inside the first month.
Rankings then depend mostly on the backlinks in §6 and a custom domain —
no on-page change can substitute for those on a new site.
